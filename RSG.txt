I. Purpose Statement

The Regent Session Gleaning (RSG) is the standard record of a working session. It exists because sessions generate real content — decisions, fragments, insights, open threads — that are lost if not captured promptly. The RSG is not a transcript. It is a gleaning: the distilled, retrievable yield of the session's work.

RSGs may be produced by the Prime, by any Regent agent, or collaboratively. Where an agent produces the RSG (as Fable / Claude often does), the Prime reviews and ratifies it. Where no RSG is produced during a session, the Prime or agent may reconstruct one from memory or session logs at the earliest opportunity.

RSGs are archived in the relevant project folder or in a dedicated Session Gleanings folder under the relevant project.

________________

II. Usage Rules

1. One RSG per session, or one per major work unit within a longer session.
2. The RSG is completed at the close of the session or immediately following.
3. Agents who draft the RSG must flag it for Prime review before it is considered ratified.
4. Ratified RSGs carry the Prime's acknowledgment (noted in the Prime Review field).
5. Unratified RSGs are preserved as-is with a note: [Unratified — Agent Draft].
6. RSGs are not canon. They are records. They do not govern.
7. No field is left blank. Use N/A or [None] where a section does not apply.

IV. Archiving RSGs

RSGs are archived in the project folder most relevant to the session's work:
  Regentorium / Core Projects / [Project Name] / Session Gleanings

Where a session touched multiple projects or was governance-focused:
  Regentorium / Governance / Session Gleanings

If no Session Gleanings subfolder exists, the RSG is placed in the nearest appropriate parent folder and a note is made in Agent Notes to create the subfolder.

RSGs use the following naming convention:
RSG_YYYY-MM-DD_[Handle].txt
Example: RSG_2026-06-18_ArchiveRename.txt

________________

V. Agent Gleaning Note (Fable / Claude and Other Agents)

It is recognized and welcomed that Fable (Claude) and other agents frequently produce session gleanings organically at the close of a session. These agent-generated gleanings are excellent raw material for RSGs. When an agent produces a gleaning:

1. The agent gleaning is preserved as-is (even if informal).
2. It is reformatted into the RSG template if it will be archived formally.
3. It is flagged for Prime review.
4. The original agent gleaning may be appended to the RSG as an attachment or noted in Agent Notes.

Agents should not wait for the Prime to request a gleaning. If the session produced meaningful output, produce the gleaning.

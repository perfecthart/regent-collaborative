I. Purpose Statement

The Project Change Memo (PCM) is the formal record of a material change to a project. It exists because changes — to scope, direction, collaborators, status, or governing alignment — need to be traceable. A project that changes silently loses its integrity. A PCM makes the change legible: here is what was, here is what changed, here is why, and here is what now governs.

A PCM is not required for every small edit or session adjustment. It is required when:
- The project's scope or primary deliverable changes materially
- The project's governing alignment changes
- The project's status changes (e.g., Active to Dormant, or Dormant to Archived)
- A collaborator or agent is added, removed, or significantly changes role
- A significant decision is made that redirects the project's direction
- A PSQ flags a change trigger
- The Prime issues a directive that changes the project

Every PCM triggers a corresponding update to the project's PO.

________________

II. Usage Rules

1. Issue one PCM per material change event (multiple related changes may be captured in a single PCM if they occur simultaneously).
2. The PCM may be drafted by an agent but must be ratified by the Prime before it is considered authoritative.
3. Upon ratification, the project's PO must be updated to reflect the change.
4. No field is left blank. Use N/A where a field does not apply.
5. PCMs are archived in the project root alongside the PO:
   Regentorium / Core Projects / [Project Name] / PCM_YYYY-MM-DD_[Handle]_[ChangeType].txt
   Example: PCM_2026-06-18_HMR_ScopeChange.txt

IV. PCM and the Disposition System

A PCM may change a project's disposition. If the change results in a disposition change, note it explicitly:

Previous Disposition: [e.g., RETAIN-Active]
New Disposition: [e.g., RETAIN-Archive]
Rationale: [Why the disposition changed]

Disposition changes to FLAGGED-Suggest Delete or PRIME DECISION-Pending require explicit Prime authorization noted in the Prime Ratification field.
